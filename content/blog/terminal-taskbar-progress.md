빌드를 걸어 두고 다른 창에서 일하다 보면, 끝났는지 보려고 터미널을 자꾸 다시 열게 됩니다. 어떤 터미널에서는 작업 표시줄 아이콘에 초록색 막대가 차오르면서 진행 상황을 알려 줍니다. 그런데 제가 쓰는 Windows Terminal에서는 Gradle 빌드를 돌려도 이 막대가 나오지 않았습니다.

이 글에서는 그 막대가 어떻게 그려지는지, Windows Terminal에서는 왜 안 나왔는지, 그리고 어떻게 고쳤는지를 차례로 적습니다.

## 터미널에 보내는 글자 중에는 화면에 찍히지 않는 것이 있습니다

프로그램이 터미널에 글자를 보내면 터미널은 그것을 화면에 그립니다. 그런데 보낸 글자가 전부 화면에 찍히는 것은 아닙니다. 정해진 모양으로 시작하는 글자 묶음은 터미널이 "글자"가 아니라 "명령"으로 받아들입니다. 글자색을 바꾸거나 커서를 옮기는 일이 모두 이렇게 이루어집니다.

이런 명령 가운데 터미널 창 자체에 무언가를 시키는 종류가 있습니다. 운영 체제 명령(Operating System Command)이라고 부르며, 창 제목을 바꾸는 명령이 대표적입니다. 작업 표시줄 진행률도 이 종류에 속합니다.

직접 해 볼 수 있습니다. Windows Terminal을 열고 아래 한 줄을 실행하면 작업 표시줄 아이콘에 절반쯤 찬 막대가 생깁니다.

```bash
printf '\033]9;4;1;50\a'
```

`\033]`가 "지금부터 운영 체제 명령"이라는 시작 표시이고, `\a`가 끝 표시입니다. 그 사이의 `9;4`가 진행률 명령이라는 뜻이고, `1`은 "진행 중", `50`은 50퍼센트입니다. 막대를 지울 때는 상태 자리에 `0`을 넣습니다.

```bash
printf '\033]9;4;0\a'
```

화면에는 아무 글자도 찍히지 않습니다. 터미널이 이 묶음을 가로채서 운영 체제에 "이 창의 진행률을 이만큼으로 표시해 달라"고 대신 전해 주기 때문입니다.

## Gradle은 이미 이 신호를 보낼 줄 알았습니다

Gradle에는 빌드가 진행되는 동안 이 신호를 보내는 기능이 이미 들어 있었습니다. 다만 아무 터미널에나 보내지는 않습니다. 신호를 이해하지 못하는 터미널에 보내면 이상한 글자가 화면에 찍힐 수 있기 때문입니다.

그래서 Gradle은 신호를 보내기 전에 "지금 어떤 터미널에서 실행 중인가"를 먼저 확인합니다. 확인 대상에는 ConEmu, Ghostty, kitty, iTerm2가 있었습니다. Windows Terminal은 이 신호를 받아 작업 표시줄에 그려 줄 수 있는데도 목록에 없었습니다.

> 기능은 이미 있었고, 터미널을 알아보지 못했을 뿐이었습니다.

## Windows Terminal을 알아보는 방법

프로그램이 자기가 어떤 터미널 안에서 실행 중인지 알아내는 방법은 대개 환경 변수입니다. 많은 터미널이 자기 이름과 버전를 환경 변수에 적어 두는데, Windows Terminal은 그렇게 하지 않습니다.

대신 Windows Terminal은 창 안에서 셸을 띄울 때마다 `WT_SESSION`이라는 환경 변수를 만들어 둡니다. 아래 명령으로 확인할 수 있습니다.

```bash
echo $WT_SESSION
```

값이 나오면 Windows Terminal 안이고, 비어 있으면 다른 터미널입니다.

이 변수는 리눅스용 Windows 하위 시스템(WSL) 안에서도 보입니다. Windows Terminal이 이 변수를 WSL 쪽으로도 넘겨 주도록 설정해 두기 때문입니다. 덕분에 WSL 셸에서 Gradle을 돌려도 같은 방법으로 알아볼 수 있습니다.

버전를 알 수 없다는 점이 마음에 걸렸습니다. 진행률 표시는 Windows Terminal 1.6부터 지원되는데, 그보다 오래된 버전인지 확인할 길이 없기 때문입니다. 1.6이 나온 지 여러 해가 지났고, Gradle 안의 다른 코드도 이미 같은 변수로 Windows Terminal을 알아보고 있어서, 변수가 있으면 지원하는 것으로 보기로 했습니다.

## 고친 뒤에 확인한 것

고친 내용 자체는 작습니다. 확인 대상에 "`WT_SESSION`이 있는가"를 하나 더했습니다. 시간이 더 든 쪽은 제대로 동작하는지 확인하는 일이었습니다.

먼저 Gradle이 내보내는 글자를 가로채서 그대로 저장해 봤습니다. 화면에는 보이지 않는 신호라서 눈으로는 확인할 수 없기 때문입니다.

| 상황 | 신호를 보내는가 |
|---|---|
| `WT_SESSION`이 있고 기본 출력 방식 | 보냄. 빌드가 끝나면 지우는 신호도 보냄 |
| `WT_SESSION`이 없음 | 보내지 않음 |
| 꾸밈 없는 출력 방식(`--console=plain`) | 보내지 않음 |
| 출력을 다른 프로그램으로 넘길 때 | 보내지 않음 |

그다음 실제 Windows Terminal에서 WSL 탭, PowerShell 탭, 명령 프롬프트 탭을 열어 각각 빌드를 돌려 봤습니다. 세 곳 모두 작업 표시줄에 막대가 차올랐고, 빌드가 끝나면 사라졌습니다. 빌드 도중에 멈춰도 막대가 남지 않는 것까지 확인했습니다.

## 아직 남은 경우

한 가지 경우는 여전히 표시되지 않습니다. 실행 창에서 `cmd`를 바로 띄우면 Windows가 그 창을 Windows Terminal에 넘겨주는데, 이렇게 열린 창에는 `WT_SESSION`이 없습니다. Gradle 쪽에서는 구분할 방법이 없어서 이전과 똑같이 동작합니다.

## 마치며

이 변경은 Gradle 9.9.0에 들어갈 예정입니다.

고친 코드는 몇 줄이지만, 그 몇 줄을 쓰려고 터미널이 글자와 명령을 어떻게 구분하는지부터 알아야 했습니다. 매일 쓰는 도구에서 불편한 점을 만나면 그냥 넘기지 않고 한 번 들여다볼 만하다는 것을 배웠습니다.
